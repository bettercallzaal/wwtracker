## What "clean on main" means here, and what it does not

Two tests, and only one of them is worth anything.

**The test that works:** which paths did the branch ADD that `main` has never
carried. **All 121 branches below add none.** Whatever they were for,
`main` has the files.

**The test that does not:** whether the branch's files are byte-identical to
`main`'s today. **Only 10 of 121 are**, and that number means
nothing. `main` has moved on - a July branch touching `lib/battles.ts` differs
from today's `lib/battles.ts` because today's was edited since, not because the
branch holds something. This repo measured the same trap yesterday: "differs
from main" said yes for 181 of 235 branches, including every one that had
merged cleanly.

**So deletion is safe here for one reason and it is worth stating plainly: every
tip sha is recorded below, and any branch can be recreated from it.** Not
because the content was proven identical, which it is not and need not be.

## What happens next

When Zaal says the word, each ref goes with

```
git push origin --delete <branch>
```

re-reading each tip immediately before its own deletion and skipping any that
moved, exactly as the 47 were retired on 2026-09-19. Any of them comes back
with

```
git branch <branch> <tip sha>
git push origin <branch>
```

Afterwards the remote holds `main`, the 70 kept branches, and whatever is in
flight. That is the "one branch and keep building" Zaal asked for, minus the
one decision nobody has made.
